# Workshop: Build an Onboarding Tracker REST API with Spring Boot

## 1. Overview
You are building the backend of an **employee onboarding tracker**. **Your job is to create a new Spring Boot project from scratch** that stores employee details in an embedded H2 database and exposes them through **two RESTful APIs**: one to capture an employee and one to fetch the captured employees.

There is no user interface. You will test your APIs with **Bruno**, an API client.

| | |
|---|---|
| **Language / Build tool** | Java 25 / Gradle (use the wrapper) |
| **Framework** | Spring Boot 3.5.x |
| **Database** | H2 (embedded) |
| **API client** | Bruno |
| **Project name** | `onboarding-tracker` (any base package you like) |

## 2. Learning objectives
By the end of this exercise you will be able to:
- Generate and structure a Spring Boot project with Gradle.
- Model a table with a JPA `@Entity` and access it with a Spring Data repository.
- Build REST endpoints with `@RestController`, `@PostMapping` and `@GetMapping`.
- Validate input and return correct HTTP status codes.
- Test APIs with Bruno.

## 3. Prerequisites
- **JDK 25.** Check with `java -version`. (If it is missing, Gradle can download one when you configure a Java 25 toolchain.)
- **Internet access** on the first build.
- **Bruno** (https://www.usebruno.com).
- An IDE of your choice (VS Code with the Extension Pack for Java, or IntelliJ IDEA).

## 4. Getting started
Create the project using **Spring Initializr** (https://start.spring.io) with these settings:

| Setting | Value |
|---|---|
| Project | Gradle - Groovy |
| Language | Java |
| Spring Boot | latest 3.5.x |
| Java | 25 |
| Dependencies | Spring Web, Spring Data JPA, Validation, H2 Database |

Download, unzip, open it in your IDE and confirm it starts:

```bash
.\gradlew.bat bootRun
```

On macOS or Linux, use `./gradlew` instead of `.\gradlew.bat`.

## 5. Your task
Implement the two APIs below. Use the **exact** paths, field names and status codes, because your work will be checked against them.

### 5.1 The employee
Each employee has:

| Field | Type | Rules |
|---|---|---|
| `id` | number | Generated by the database. The client never sends it. |
| `name` | text | Required, not blank. |
| `role` | text | Required, not blank. |
| `onboardingDate` | date | Required. Format `yyyy-MM-dd`, for example `2026-11-10`. |

### 5.2 API 1: capture an employee
`POST /api/employees`

Request body:
```json
{ "name": "Asha Rao", "role": "Engineer", "onboardingDate": "2026-11-10" }
```

| Case | Response |
|---|---|
| Valid request | `201 Created` with the saved employee, including its generated `id` |
| A required field is missing or blank | `400 Bad Request` |
| `onboardingDate` is not a valid `yyyy-MM-dd` date | `400 Bad Request` |

Example `201` response:
```json
{ "id": 1, "name": "Asha Rao", "role": "Engineer", "onboardingDate": "2026-11-10" }
```

### 5.3 API 2: fetch employees
`GET /api/employees`

Returns `200 OK` with a JSON array of every saved employee. Return an empty array `[]` when nothing has been saved yet.

### 5.4 Database
- Use an **embedded H2** database with Spring Data JPA.
- Data should survive an application restart (use a file-based H2 URL, for example `jdbc:h2:file:./data/onboardingdb`).
- Enable the H2 console so you can inspect the table.

### 5.5 Requirements checklist
- [ ] The project builds and starts with `gradlew bootRun`.
- [ ] `POST /api/employees` saves an employee and returns `201`.
- [ ] `GET /api/employees` returns everything saved.
- [ ] Invalid input returns `400`, not `500`.
- [ ] Dates are returned as `yyyy-MM-dd` strings, not arrays or timestamps.
- [ ] The H2 console is reachable and shows an `employees` table with your rows.

## 6. Testing with Bruno
1. In Bruno, create a collection named `Onboarding Tracker`.
2. Add a **POST** request `Create Employee` to `http://localhost:8080/api/employees`, with a **JSON** body.
3. Add a **GET** request `Get Employees` to the same URL.
4. Send the POST a few times with different employees, then send the GET and confirm they all appear.
5. Test the error cases: an empty `{}` body, a missing `role`, and `"onboardingDate": "10-11-2026"`. Each must return `400`.

If port 8080 is already in use on your machine, start the app on another port:
```bash
.\gradlew.bat bootRun --args="--server.port=8081"
```

### Troubleshooting
| Problem | Fix |
|---|---|
| `Web server failed to start. Port 8080 was already in use` | Stop the program using the port, or start on a different port as shown above. |
| `415 Unsupported Media Type` | In Bruno, set the request body type to **JSON**. |
| `Cannot find a Java installation ... languageVersion=25` | Install JDK 25, or add the `org.gradle.toolchains.foojay-resolver-convention` plugin to `settings.gradle` so Gradle can download it. |
| Dates come back as `[2026,11,10]` | Make sure the field is a `LocalDate` and you are using Spring Boot's default JSON setup. |

### Hints
- Packages to think about: `model` (entity), `repository`, `controller`.
- `JpaRepository` already gives you `save` and `findAll`.
- `@Valid` on the request body plus `@NotBlank` and `@NotNull` on the entity does most of the validation.
- A `@RestControllerAdvice` class can turn validation failures into clean `400` responses.
